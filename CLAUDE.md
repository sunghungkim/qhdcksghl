# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static website for **봉찬회 · 봉불사** (a Korean Buddhist pilgrimage group and its temple). Visitors read pilgrimage/event schedules, the temple intro + history, a photo gallery, and can reserve trips; the owner (관리인) manages the same data from admin pages on the same site. **All user-facing text is Korean**, and the owner reads large, warm, easy-to-read UI as a requirement (base font 19px, warm palette in `theme.css`).

`PRD.md` is the *original* plan (5 pages, a `cafe-ai` Edge Function, open reservation inserts). The project has outgrown it — trust this file and the code, not the PRD. The `cafe-ai` Edge Function was never built.

## Run / verify

- **No build, no npm, no lint, no tests.** Plain HTML/CSS/JS files (only external dependency: Google Fonts via `@import` in `theme.css`). Don't introduce bundlers, `package.json`, or frameworks.
- **Serve over HTTP, never `file://`** (the shell uses `fetch` to check pages exist): from the project folder run
  `powershell -NoProfile -ExecutionPolicy Bypass -File serve.ps1 [-Port 8780]` → http://localhost:8780/ . It dies on reboot; Python/Node are not installed. Preview tricks: `?popup=1` forces the entry popup, `?nopopup` suppresses it.
- In the Claude desktop preview pane, every edit auto-opens a `file://` tab that renders wrongly — close it and use the `http://localhost:8780` tab. The pane is very narrow (~270px); resize to 375px (phone) / 1280px (desktop) when judging layout.
- Verification is by browser (JS console / screenshots). DB logic was verified with SQL `DO $$ … raise exception 'TEST …' $$` blocks, which roll back and leave no data.

## Architecture

**`index.html` is the shell**: header + left menu (becomes a top bar ≤760px) + a center area. Home content is inline; every other page is a separate HTML file loaded into an `<iframe>`, chosen by URL hash (`#temple`; a `:target` suffix passes `?to=target` to the page, e.g. `#temple:info` jumps to 절 소개's contact card — the home "연락처 · 오시는 길" button). The menu is the `PAGES` array in its script (a `HEAD` fetch shows "준비 중" if a file is missing; `login` is a hidden entry, not in the menu). **Sub-pages must not include their own menu.** The phone number shows bottom-left of the sidebar on desktop and, on phones (≤760px, where the sidebar becomes a top bar), as a tappable `.call-bar` strip under the menu on every page. Menu order: 홈, 절 소개 `temple.html`, 성지순례 일정 `pilgrimage.html`, 행사 일정 `events.html`, 내 예약 `reserve.html`, 동행의 기록 `gallery.html`; plus `login.html`.

**Admin pages** are standalone (not in the menu; reached from header links after admin login): `menu.html` (행사 관리: add/edit pilgrimages & events, D-5 red), `sales.html` (매출), `reservations.html` (전체 예약: confirm/cancel). Each has its own top bar and a fallback admin login form.

**Shared files** (loaded by script/link tags, no modules): `theme.css` (all tokens + shared components: cards, buttons, forms, popup, slideshow, pager, search bar, to-top button), `paging.js` (`paginate`, `searchBox`, `matchesQuery` — 5 per page on 성지순례/행사 and on admin `menu.html`, 6 on gallery; `paginate` opts `startPage`/`onPage` let menu.html keep the page after an edit), `carousel.js` (`buildCarousel`, home photo list `HOME_SLIDES`), `flyers.js` (the pilgrimage flyer photos `FLYERS` + `buildFlyerBox`), `popup.js` (entry popup, config object `POPUP`, which reuses `FLYERS`), `pay.js` (입금 계좌 팝업 `showPayPopup` + 확인 팝업 `askPopup`), `story.js` (절 소개 "봉찬회에 대하여…" text + `buildStory`), `totop.js` (`addToTopButton`, used on `temple.html`). Cross-page state lives in `sessionStorage` (`admin_token`, `member`); iframe pages read the member with `window.top.getMember()` and refresh the header with `window.top.renderWho()`. Media: `images/` (home photos `buddha`/`slide-*`/`hero.jpg`; `images/flyer/` flyers; `emblem.png` is unused; `logo-bongbulsa.png` / `logo-bongchanhoe.png` = transparent red calligraphy used both in the shell brand link (top-left, replacing the text and the wheel emblem); `logo.png` (wheel) is currently unused — the home hero no longer has a title logo), `video/temple-intro.mp4`, `일정/` (original flyer photos).

Page-specific behaviors worth knowing:
- **Home**: photo slideshow (8 photos, 5s auto-advance left, dots + arrows) and a two-line tagline whose 2nd line is aligned under "는" via an invisible `.tag-pad` copy of the text. The entry popup shows each visit; only its button "오늘 하루 보지 않기" hides it until midnight (`localStorage['entry-popup-hide']` = `{id, until}`); closing otherwise stores nothing. The top-left brand link ("봉불사 / 성지순례 봉찬회" in the shell) reloads the site at the home page and sets `sessionStorage['popup-skip-once']` so that one reload skips the popup. The popup and the flyer box above the search bar on 성지순례 일정 share one list: edit `FLYERS` in `flyers.js` (photos in `images/flyer/`, and change `FLYERS.id` so earlier dismissers see the new popup).
- **절 소개**: intro video (autoplays muted — it has audio — with "🔇 소리 켜기", centered "↻ 다시 보기" when it ends, "▶ 재생" if autoplay is blocked) → history/meaning section (`story.js`; text copied from the owner's two `.hwp` files, with the start year deliberately set to **1985** in both places) → contact card `#temple-info` (links list `LINKS`, map embed, phone). `temple_info.image_url` is no longer used.
- **성지순례/행사 일정**: upcoming + past groups, search, pagination; 예약하기 on a pilgrimage card needs a member login.
- **Gallery**: admin uploads photos (resized to ≤1600px JPEG in the browser) to Storage bucket `gallery` + table `gallery`; visitors view, search, open a lightbox.

## Auth model (two separate logins, both on `login.html`)

- **Admin** = Supabase Auth email/password; token in `sessionStorage['admin_token']`. RLS treats **any `authenticated` user as admin**, so public sign-ups must stay disabled. Logout (shell or admin pages) clears it and goes to `#login`.
- **Member** (아이디 = 이름, 비밀번호 = 전화번호) via the `member_login` RPC. **Open mode is currently ON** (`site_settings.member_login_open = 'true'`): any non-empty name+phone "logs in", so member status proves nothing yet — never gate personal data on it. To enforce the list: fill `members`, then `update site_settings set value = 'false' where key = 'member_login_open'` (then 5 wrong tries/name/10 min locks). Non-members can always browse everything.

## Reservations & stock

예약하기 on a 성지순례 card **requires a member login** (logged out → "로그인하기" prompt) and opens a panel: the booker's 이름+전화번호 (read-only, from the session) plus, for 인원 N ≥ 2, N−1 extra 이름+전화번호 rows (all required; sent as `p_companions` jsonb, stored in `reservations.companions`, validated server-side → reason `need_companions`; shown on 내 예약/전체 예약), 차량 탑승지 buttons (place + time, from `pilgrimages.boardings` jsonb `[{place,time}]`, required when the trip has any), 인원 → `member_reserve(p_name,p_phone,p_pilgrimage_id,p_people,p_note,p_boarding,p_companions)` (name+phone go through `member_check`; boarding must match a listed "place time" else reason `need_boarding`; stored in `reservations.boarding`; direct anon inserts into `reservations` are blocked; one active reservation per person per trip). After a successful booking `pilgrimage.html` pops up the 입금 안내; `pay.js` (shared, also used by `reserve.html`, which has a "입금 계좌 보기" card at the top and a button on each pending reservation) holds `showPayPopup` and the bank accounts in its `ACCOUNTS` array (복사 buttons, "입금 확인 후 예약 확정" note). **Reservation stages:** `requested` (입금 대기, label shown to the member) → member presses 입금 완료 in 내 예약 (`mark_reservation_paid` RPC, sets `paid_at`) → `paid` (예약 접수) → admin presses 예약 확정 (`confirm_reservation`, accepts requested/paid/canceled) → `confirmed` (예약 확정); members can cancel only `requested`, `paid`/`confirmed` need a phone call; admin 전체 예약 opens on the 예약 접수 tab. **No auto-cancel:** pending (`requested`) bookings stay until the admin confirms them or someone cancels them (the earlier 2-hour auto-cancel, `expire_stale_reservations` and the countdown timer were removed on request). Admin 전체 예약 has a search box (이름, 전화번호 incl. partial digits, 일정, 탑승지, 동행인; searches inside the chosen status tab) and 5 cards per page. Admin can re-confirm a `canceled` booking ("다시 확정 (입금 확인)", e.g. paid after the 2h auto-cancel; `confirm_reservation` accepts requested or canceled, re-takes the seats, refuses with `duplicate` if the person re-booked meanwhile). Members can cancel only `requested` bookings; `confirmed` ones show "취소는 전화 02-387-8578". `menu.html` edits `boardings` as a textarea, one stop per line ("장소 시간"). `my_reservations` returns `boarding`; it lists only reservations whose name+phone equal the login identity. `reserve.html` lists/cancels via `my_reservations`/`cancel_my_reservation`. `pilgrimages.remaining` (empty = unlimited) is decreased only by `record_sale` and the admin `confirm_reservation` (which refuses if seats are short); `admin_cancel_reservation` of a confirmed booking returns the seats; the sync trigger keeps `remaining` in step when `capacity` is set/changed — so counting only starts once an admin enters a trip's 정원.

## Conventions and gotchas

- Korean line breaks: `theme.css` sets `word-break: keep-all` (break only at spaces) + `text-wrap: pretty/balance` for every page; don't override per page unless a long URL needs `overflow-wrap: anywhere`.
- Render DB/user data with `textContent`/DOM builders, never `innerHTML` (every page follows this). The global `[hidden] { display: none !important }` in `theme.css` is relied on.
- Photos/video of 법회 show congregants' faces and donor names (등 이름표); the owner has been warned — don't publish more without asking.
- A bulk regex edit once silently deleted a whole block of the home page; after scripted multi-line edits, re-open the page and check it.
- Editing wording: `story.js` (역사 text), `carousel.js` (`HOME_SLIDES`), `flyers.js` (`FLYERS`: flyer photos for 성지순례 page + popup), `popup.js` (`POPUP`), `temple.html` (`LINKS`), `index.html` (`PAGES`, tagline).
